# 交付韌性：讓任何人在任何地方打開都不會出事

一份 HTML 交出去之後，會被打開的地方遠比想像多：聊天軟體的內建預覽、郵件用戶端、公司電腦的舊瀏覽器、沒有網路的會議室、手機、印表機。**每一種都可能砍掉一部分能力。**

使用者的要求：**「我希望盡量萬用，不要有人遇到問題。」**

---

## 一、三層降級原則（最重要的一條）

把頁面拆成三層，**上層壞掉不能影響下層**：

| 層 | 內容 | 壞掉的後果 | 對策 |
|---|---|---|---|
| **第一層：靜態 HTML** | 全部文字、表格、選項、圖說 | 使用者什麼都看不到 | **內容一律寫死在檔案裡，禁止用 JS 生成** |
| **第二層：JS 互動** | 標記、篩選、跳轉、狀態模擬 | 讀得到但不能操作 | 頁面自己偵測並顯示替代做法 |
| **第三層：需要權限的動作** | 剪貼簿、下載檔案、localStorage | 存不了、匯不出 | 每個都 try/catch，並提供第二條路 |

### 這條規則是怎麼來的（真實事故）

2026-08-14，第一版確認台把 12 則卡片寫成 JavaScript 在開檔時生成。使用者用內建檢視器打開 `file://` 檔案，該檢視器不執行內嵌 JS——**整份內容一片空白**，只剩靜態的開頭與結尾。使用者的原話：「我沒看到啊？」

**內容用程式生成 = 把內容押在一個隨時可能被關掉的功能上。**

### 實作樣式

```html
<!-- 互動元件預設隱藏，JS 跑起來才開 -->
<div class="tools jsonly" style="display:none">…</div>
<!-- 降級說明預設顯示，JS 跑起來才藏 -->
<div class="hint warn" id="hintNoJS">這個檢視器沒有執行互動功能…</div>
```
```js
document.querySelectorAll(".jsonly").forEach(el => el.style.display = "");
document.getElementById("hintNoJS").style.display = "none";
```

## 二、已知的環境陷阱與必做的預防

| 環境 | 會壞什麼 | 必做的預防 |
|---|---|---|
| 沙箱／內建預覽器（聊天軟體、郵件、檔案預覽） | **完全不執行 JS** | 內容全部靜態；互動元件預設隱藏由 JS 開啟；備一段降級說明預設顯示 |
| `file://` 直接開檔 | localStorage 可能被拒 | 存取一律包 try/catch；失敗時把「自動保存」字樣改成明顯警告 |
| `file://` 直接開檔 | `navigator.clipboard` 需要安全來源，多半失效 | 必須有 `document.execCommand("copy")` 後備路徑 |
| `file://` 直接開檔 | `fetch` / `XHR` 被同源政策擋死 | 不要用 fetch 載任何東西，資料寫在頁面裡 |
| 公司內網／無網路 | CDN、Google Fonts、遠端圖片全部載不到 | 零外部請求；字型只用系統字型堆疊；圖片轉 data URI |
| 嚴格 CSP 的檢視器 | 外部資源與部分行內行為被擋 | 不引用任何外部網址；事件用 `addEventListener`，不要寫 `onclick="…"` 屬性 |
| 郵件系統 | 擋 `.html` 附件 | 交付訊息先講：被擋就壓成 zip 再寄 |
| 下載被沙箱擋 | 「匯出檔案」按了沒反應 | **複製到剪貼簿是主要通道，下載是備援**，不可反過來 |
| 印表機／存 PDF | 按鈕印出來、卡片被切成兩頁 | `@media print` 藏互動元件；卡片 `break-inside:avoid`；被篩選隱藏的內容在列印時強制顯示 |
| 手機 | 版面爆開、表格擠成一團 | 響應式；寬表格放進可橫向捲動的容器 |
| 深色模式 | 背景透明、文字看不見 | `body` 必須明確指定背景色；深淺兩套色票都要完整定義，不可只寫在 media query 裡 |
| 中文檔名 | 某些工具、網址、腳本會處理失敗 | 檔名可用中文（使用者要看得懂），但**同時放一份 ASCII 檔名副本**給工具與預覽網址用 |
| 使用者清快取／換電腦 | 填到一半的草稿消失 | 匯出鍵放最顯眼處；頁尾明講「換瀏覽器或清快取就會不見」 |

## 三、降級時要有話講

不要假設使用者知道自己踩到哪個限制。**要講「現在該怎麼辦」，不是「發生了錯誤」。**

> 反例：靜靜地什麼都不做。
> 正例：「這個檢視器沒有執行互動功能——內容你全部讀得到，但標記按鈕不會動。要標記的話，用檔案總管找到這個 .html，按右鍵→開啟檔案→選 Chrome 或 Edge；不想換也可以，直接在對話裡寫『A1 選第一個』就行。」

## 四、先跑機器驗證，再談人工檢查

```powershell
$skill = "$env:USERPROFILE\.claude\skills\html-first-workflow"   # 技能安裝在別處就改這一行
python "$skill\scripts\validate_html.py" "<產出檔.html>"
```

它會自動判斷是確認台還是展示頁，逐項檢查：零外部相依、關掉 JS 還讀不讀得到內容、有沒有內聯事件屬性、viewport、列印樣式、深色定義、body 背景色、身分證格式、可能撞到真人的手機號；確認台再加驗 `.jsonly` 預設隱藏、無 JS 替代說明、DOC_ID 有沒有忘了改、每個選項有沒有寫「影響」與「代價」、兩條回收路徑都在。

**最後一行必須貼進交付訊息**，接在四行版本區塊後面：

```
validate: PASS (15/15) — 協作確認台_專案名_v1.html
```

**沒貼那一行＝沒交付。** 使用者不用懂內容，只要看那行在不在——這是把「AI 自律」換成「使用者一眼可稽核」的地方。

未通過就不准交付。這支腳本存在的理由：這個技能的三次失敗全都是「AI 自認完成」的產物，自評表擋不住長會話尾段的偷懶。

## 五、機器驗不到的，才靠人工檢查表

1. **關掉 JavaScript 還讀得到全部內容嗎？**（最重要）
2. 在瀏覽器實際開過，主要互動都按過一遍了嗎？
3. Console 有沒有錯誤？有沒有全域變數外洩（用 IIFE 包起來）？
4. 有沒有任何外部網址（CDN、字型、圖片、追蹤碼）？
5. 深色模式看得清楚嗎？手機寬度爆版嗎？
6. 列印預覽乾淨嗎？
7. 剪貼簿與下載都試過了嗎？失敗時有替代路徑嗎？
8. 檔名有沒有 ASCII 副本？

驗證方式：用 `.claude/launch.json` 起一個靜態伺服器指向產出資料夾，在瀏覽器實跑。
**驗證用的暫時設定，交付定稿後要移除並回報。**
