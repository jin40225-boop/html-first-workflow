# 功能編排與製程規格 v1

> **版本**：v1 · 2026-10-20 負責人核可（S-3「照建議」）。
> **和設計規格的分工**：`design-system.md` 管「長相與操作」（數值、元件、R-01～）；本檔管它沒寫的三塊——
> **功能怎麼擺、資料怎麼進出、怎麼做與怎麼驗收**。兩份都是**開工前必讀**。
> **為什麼有這份**：負責人原話「我每次新軟體都要復述我對網頁或軟體設計的UI和元件、美術、功能編排的需求、新理念……」。
> 下面每一條都是他講過、而且被重講過的事；寫在這裡，就不該再讓他講第二次。
> **改這份**：照 `design-system.md` 第十節同一套升版提案流程，版號 +1，條目後面附原話與日期。

每條格式：**規則**（要／不要）→ 原話 → **判準**（怎麼檢查做到了沒）。

## 一、功能編排（F）

| # | 規則 | 原話 | 判準 |
|---|---|---|---|
| **F-01** | **以服務對象為中心先畫流程脈絡，再分「兩張臉」**：先畫主流程（例：接案→評估→計畫→執行／資源→追蹤→結案），再把每個子功能拆成「**對象面**」（嵌在單一對象頁的單筆動作＋狀態）與「**業務面**」（整批處理的工作台）。報表、批次通知、盤查舊資料、改別人的案子留在業務面 | 「全部都是基立於個案服務上，個案管理系統其實就是核心」「用專家姿態釐清邏輯脈絡、關聯性，推論如何整合」（2026-10-12） | 交付的流程圖上，每個功能都標了「對象面／業務面」；整合驗收時，從一個對象出發不切分頁、不重找人就能走完一條龍 |
| **F-02** | **跨系統入口要顯眼，不用教就找得到**：從對象頁到其他子系統的入口做成大按鈕、按鈕上直接寫狀態（例：「已轉介・待受理」）；子系統頁籤分組、帶圖示與系統色、帶待辦數 | 「轉〔某子系統〕等等按鈕都藏在角落……我還要教育訓練或提醒大家位置……這樣太不明顯，太低調了」（2026-10-14） | 新同仁不經說明，10 秒內在畫面上找到入口；入口不在選單裡、不在角落。介面數值見 `design-system.md` R-19 |
| **F-03** | **首頁問候橫幅的待辦捷徑最多顯示 3 個＋總數**，超過收合、點了展開；**只限這一處，不推廣** | 「超過三個就收縮，要點開才會顯示全部，只顯示三個、和目前待處理的人數。」（2026-10-14，看首頁問候橫幅時說）；「其實我並沒有覺得一定最多只能三個，只是因為這個有決策。不需要套用到全部。」（2026-10-20） | 問候橫幅待辦超過 3 個時只露 3 個＋總數；其他膠囊列照實全列，要收合先問。教訓：單一畫面的裁決不要自行升格成通用規則。見 `design-system.md` R-17 |
| **F-04** | **「待處理」數字只算「別人在等你或已逾期」**；快到期、比對提醒、留言照列，但標「提醒」、不進數字 | 負責人選「別人在等你或已逾期才算」（2026-10-14） | 每個數字卡都寫得出「這個數字算哪幾類」；提醒類不會讓紅點變大。見 `design-system.md` R-18 |
| **F-05** | **提醒只能由完成動作解除**；期限用里程碑倒數顯示（D-3／今天／逾期 2 天） | （主模型提出、負責人未推翻）「之後記任何一筆服務就自動解除」（2026-10） | 沒有「關掉提醒」按鈕；解除條件寫在提醒旁邊 |
| **F-06** | **讀既有資料自動成文，不重打**：通知、公告、當日手冊、報表文字從系統裡已有的資料帶入，人只改不打 | 「讀既有資料自動成文，不重打」（專案介面規範，2026-10-06） | 產出文字的畫面上，每一段都標得出資料來源；同一個資訊不需要打第二次 |
| **F-07** | **已核定的成品＝功能基準，新系統不得縮水**：重構或整合時，舊版負責人核定過的功能、操作，新版都要有 | 「v2 是我要的！我已經核定了。」→「必須做到 v2 的功能與操作，不得縮水」（2026-10-13） | 開工前列「已核定功能清單」，交件時逐項打勾；少一項要先問 |

## 二、資料進出（D）

| # | 規則 | 原話 | 判準 |
|---|---|---|---|
| **D-01** | **和 Excel 共存先判面向，再取工具**：① 輔助／外掛（Excel 仍是正本，軟體能寫回 Excel）② 替代（Excel 退成存檔＋匯出）③ 兩者之間（同一欄只在一處決定，定期對帳）。工具箱（貼上、比對、寫回、對帳、匯出）依面向取用，不是固定步驟 | 「突破性的思維是原來軟體可以跟 EXCEL 聯動，製作輔助、外掛、優化、替代性軟體」 | 開工文件第一段寫明這套落在哪個面向、為什麼；改 Excel 正本（公式、VBA）只在負責人授權時做 |
| **D-02** | **欄位對齊 Excel**：基本資料照 Excel 原欄名、原順序；標欄位字母；下拉選項取自既有詞彙 | （負責人指出基本資料與 Excel 不契合後）改為總表原名原序（2026-10-07） | 畫面欄位和 Excel 表頭並排，名稱與順序一致 |
| **D-03** | **匯入／比對的標準動作**：乾跑 → 對帳報告 → 對得上才寫入；差異逐筆列出、人按了才改、**不自動覆蓋**；貼上即比對 | 「我希望妳直接強化這個功能，變成把資料貼給你，你就會啟動比對。」 | 匯入預設不寫；有「差異 N 筆」清單；沒有任何一條路徑會不經確認覆蓋既有資料 |
| **D-04** | **外部資料直接進正式紀錄，標醒目「待認領」**；定期自動刷新＋可手動刷新；**不在畫面上多設一道收件匣** | 「這些鎖死制度也造成困難與不方便」；「直接進個案資料並明顯標『待認領』，取消多步驟認領」（2026-10-05） | 外部報名到正式紀錄只要一步「認領」；資料層仍保留可重跑、可駁回（兩者不衝突） |
| **D-05** | **舊系統換新：操作與資料延續、程式全新**——能移植就移植、沿用同仁習慣悄悄換新（舊捷徑全轉接、舊資料唯讀保留、同仁照舊點就是新版）；和「重構就是全新軟體」並存 | 「為何？直接移植現在的不就好了，為何要改？」；「沿用同仁習慣、悄悄換新」 | 舊入口全部還能用且開到新版；舊資料有搬移計畫並驗過筆數 |
| **D-06** | **只有真正必填才必填**（例：新增一筆只要「姓名＋一個識別碼擇一」）；缺漏只在用得到它的那張表標示 | 「只有真正必填才必填」（專案介面規範） | 新增表單的必填欄 ≤ 2–3 個；缺漏提示出現在要用那欄的畫面，不是新增時 |

## 三、製程（P）

| # | 規則 | 原話 | 判準 |
|---|---|---|---|
| **P-01** | **出題前先對照「已定案」**：把設計規格、本檔、專案決策紀錄、總綱裁決、記憶裡的規則列成一張「已定案清單」，每道題先對一次，**已定的不問**，只把它列成「已定案、照做」。每題附「專家補充」：他沒提、但實務上會遇到的操作與例外 | 「我其實已經有選定字形了？為何這裡好像沒有？」（2026-10-20）；「你要擔任專家提供我沒想到的解決方法，而不是問我」 | 每份確認台／題目清單的開頭有「已定案、不再問」一欄；字型、主按鈕色、數值這類規格項目從不出現在題目裡 |
| **P-02** | **決策怎麼問、答案怎麼收**：他在場就在對話裡分批問（每批 ≤ 4 題）；不在場才用 HTML 台，HTML 台只看操作；答案一定落檔，由 AI 主動收回。收到後白話複述、指出和其他答案的衝突，再寫回決策紀錄 | 「七題直接在對話框問我」；「欸我剛剛寫了那麼多」（答案只存在瀏覽器裡，關掉就沒了） | 沒有任何決策只存在瀏覽器 localStorage；決策紀錄裡每條有日期與原話（＝`design-system.md` R-16） |
| **P-03** | **他拿別的 AI 做的 HTML 當規格時：保留視覺與結構，只加不減** | 「我要你用跟我設計 html 的方式…然後再叫 agent 去更新」 | 和他給的 HTML 並排，原有區塊、按鈕、排版一個不少 |
| **P-04** | **待核可的東西一出版就進待問清單**，每次收工逐項帶，不能靠記得 | 「……已經講了好幾次了，一直沒有完成？」（2026-10-15） | 收工回報有「待你核可」一節，列出所有已出版未答的預覽與草案 |
| **P-05** | **原型要完整**：功能全做；資料全部是假的，但表格、格式、排版、關聯照真的；還沒接上的外部服務做成標示清楚的示範模式，不留白 | 「我要完整，一切以完整為主」；「範例要完整。但都使用建立的範本與假資料（表格和格式、排版、關聯都是真實會使用的，但資料是假的）」 | 原型裡每個按鈕點了都有反應；示範模式有明顯標示 |
| **P-06** | **重構盤點時，低用量功能先對照原始構想，判「重做」不判「刪除」**；重構產出不寫應急、止血段落 | 「是因為不好用，所以導致使用率下降」；「絕對不准救急、止血」 | 盤點表每個低用量功能都有「原始構想」與「重做方向」兩欄；文件裡沒有「先暫時」「應急」 |

## 四、驗收（V）

| # | 規則 | 原話 | 判準 |
|---|---|---|---|
| **V-01** | **交件四件套**：① 冷啟動（空資料夾從捷徑開）② 實際操作（點畫面）③ 同規格同格式的假資料（照真檔結構產）④ AI 模擬人工操作並截圖。單元測試全綠不算交件 | 「後續測試進行冷測試、實際操作測試、生成同樣規格格式的假資料，用AI模擬人工操作的模式進行測試。」 | 交件回報四件各有證據（截圖、指令原文、資料檔位置） |
| **V-02** | **部署在共用資料夾的程式，驗收分三層**：本機＝回歸；從共用資料夾的驗收副本用網路路徑實跑；在另一台使用者電腦現場檢核 | 「本機環境和實際使用環境根本不同，為何是這樣測試？」 | 回報分三段寫，不把本機結果寫成「已驗收」 |
| **V-03** | **不採信自述**：沒有 commit 與測試原文的回報不收；檢查器好壞各驗一次（好的會過、壞的會紅）；數字全過也要並排用眼睛看 | 「不採信自述」 | 回報附 commit、測試輸出原文；每個新檢查附一個「故意弄壞會紅」的證據 |

## 五、新軟體開工清單

### 開工前 AI 自動讀（不用他說）
- [ ] `design-system.md`（長相、操作）＋本檔（功能怎麼擺、資料進出、驗收）
- [ ] `library/INDEX.md`＋本機軟體資料庫 `INDEX.md`（有沒有現成的）
- [ ] 專案自己的決策紀錄／總綱裁決／記憶：**列成「已定案清單」**（P-01）
- [ ] 重構案：舊系統只當資料與邏輯來源；低用量功能先找原始構想（P-06）
- [ ] 有舊 Excel：先判共存面向（D-01）；讀真檔只讀結構，不讀個資
- [ ] 要新美術：照 `art-commission-pipeline` Skill，不自己畫

### 先給什麼 HTML
- [ ] 主畫面照 `design-system.md` 第五節骨架
- [ ] 整合或多子系統：先畫流程脈絡，標「對象面／業務面」（F-01）
- [ ] 每題附「▶ 試給我看」；示範資料全假，但欄名、格式、排版、關聯照真檔（P-05）
- [ ] 待辦口徑、膠囊收合、跨系統入口、確認三級：直接照規格畫，不當題目

### 問什麼
- [ ] 只問「答案只有他知道」的事；每題寫「選了會怎樣」＋「代價」，推薦項放第一
- [ ] 每題附「專家補充」
- [ ] 他在場就在對話裡分批問；答案寫回決策紀錄（P-02）

### 不問什麼
- [ ] 規格已定的數值、字型、形狀、主按鈕色
- [ ] 他講過的業務規則（列成「已定案」）
- [ ] 純技術取捨（資料結構、檔案放哪）——自己決定、說明理由
- [ ] 要不要做應急補丁；要不要刪低用量功能

### 交件前
- [ ] V-01 四件套；共用資料夾部署的照 V-02 三層
- [ ] 1440 桌機截圖、四行版本、`validate: PASS (n/n)`；回報附 commit 與測試原文
- [ ] 待核可的東西全部列進待問清單（P-04）
- [ ] 結案問「留不留」＋「規格升版提案」（含本檔）

## 六、領域範例：身障服務整合案（2026-10-20 負責人核可 S-4、S-5）

> **這一節不是通用規則。** 它們是某個身障服務整合案（多個子系統收攏成一套、社工／治療師／督導分工、個案業務）裡負責人定案的做法。
> **什麼時候照抄**：新系統同時符合「以個案為中心」＋「有督導與第一線的分工」＋「同一個人可能在多個子系統出現」時，照抄並在交付訊息寫「沿用領域範例 X」。
> 不符合的系統（活動報名、物資、單純表單）不要硬套；要用就先問一句。

### 範例 1：身分與入口——每人一個捷徑（S-4：本案規則）
- **做法**：一套程式；每人一個捷徑，捷徑帶身分，不設登入、不綁作業系統帳號；切成督導時輸一次督導密碼，本次開啟有效；社工、治療師不用密碼。
- **原話**：「全中心還是收攏只有一個軟體可以使用各項工具與功能。但用捷徑來當作帳號選擇機制，然後督導的帳號則要額外輸入一次帳號。我覺得是最好的辦法。」（2026-10-20）
- **例外——共用電腦**：如果工作站是好幾個人輪流用同一台（例：倉儲、櫃台工作檯），每人捷徑會被別人點到，**改「一個入口、頂端選身分」**。這是同一位負責人在另一個共用電腦的系統裡定過的結論，兩個結論的差別在使用情境。
- **判準**：開工時先判「這套是不是共用電腦用」，寫在開工文件；不當題目問。

### 範例 2：督導「直接執行」（S-5）
- **做法**：需要雙方同意的動作（例：交換案子），督導多一顆「直接執行」，對方只收到清單通知；第一線發起的一律走核可；批量動作一批一位接收人。
- **原話**：「新增不需要雙方同意的模式——督導直接操作交換案子，對方只收到清單通知」
- **判準**：每個需要核可的動作都寫得出「誰發起走核可、誰可以直接執行」。

### 範例 3：人工檢核台的固定形狀（S-5）
- **做法**：系統產清單 → 證據並排 → 一鍵決定 → **永久記得**（不再提醒）→ 進度條。疑似同一人時跳「快速對照確認」，不自動合併。
- **原話**：「增加一個快速的人工決策與對照程序即可。」
- **判準**：同一組判定過一次後不再出現；沒有任何自動合併。

### 範例 4：通知三階＋依分級升級＋督導總覽（S-5）
- **做法**：已送出 → 已查閱 → 已處理；逾期未查閱才依分級升級；督導總覽可再提醒、延長、結束，全部留痕。**所有通知共用同一套機制**。
- **原話**：「此機制為所有通知共用，不只併案」
- **判準**：任一則通知都看得到三階狀態；升級條件寫在督導總覽上。
