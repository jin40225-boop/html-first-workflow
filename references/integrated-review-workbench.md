# 操作體驗＋決策確認綜合台

骨架：`assets/integrated-review-workbench-template.html`

## 何時使用

新建軟體、重整資訊架構或改變主要工作流程時，預設使用綜合台。使用者先在同一份 HTML 實際操作，再切到八節決策確認，不必在展示頁與確認台之間來回比對。

若需求只有政策、文案或無法合理做成操作畫面，使用獨立 `review-console-template.html`。需要交給客戶看、且不應顯示內部不確定性時，另做 `client-demo-template.html`。

## 同一份 HTML 的兩個區域

### 操作體驗

- 第一畫面直接呈現最常做的工作，不先做首頁儀表板或功能總覽。
- 依真實任務分入口；同一工作所需的新增、附件、設定及完成動作留在同一個抽屜或對話框。
- 所有主要按鈕都要有實際行為、保存結果及失敗回饋。不可執行時，顯示原因與處理方法。
- 操作資料只供預覽，必須明寫保存位置、是否跨重開保留、是否連到正式 API。
- 「試用做法」只改變操作體驗設定，不改決策答案。

### 決策確認

- 固定按理解、現況、計畫、規格、矛盾、提問、決策、成本八節排列。
- 可直接引用操作體驗中的畫面或狀態，避免使用者憑想像拍板。
- 新問題初始未回答；推薦選項可以醒目，但不可預選或自動核准。
- 試用、草稿與已保存意見是三種不同狀態。選選項、填補充或按四態只形成草稿；每題必須另按「保存本題」才成為已保存意見。
- API 型確認台只在 API 成功後顯示保存成功；409 保留草稿並提示重新載入。離線骨架只能聲稱「已存入本瀏覽器」。

### 「▶ 試給我看」（公版必備，2026-10-01 使用者明定）

使用者原話：「不確定怎麼選然後可以跳示範這裡，就是我要的……AI 就是應該要這樣跟我合作。」

- **每一題必答卡都要有一條試用列**：`不確定怎麼選？［▶ 試給我看：按了會跑什麼］`。按下去要切到操作體驗、**真的改變畫面**（切換報表單位、跑一段流程、開出那個作業視窗），並用底部泡泡說明「看哪裡、跟選項有什麼關係」。
- **題目示範不出來，就是題目還沒準備好。** 計數口徑、命名規則、並行與鎖、號碼規則這類靜態畫面看不出差別的題目，要做成可切換的模擬；做不出來就先別問。v2 曾因此被退：「太陽春，很多功能示範都無法呈現，我無法進行回答。」
- **操作區頂端放「這一版可以操作的 N 件事」索引**：每格按下去帶到那裡並實際跑一次；另可加「▶ 從頭跑一次完整流程」導覽。
- 示範只改操作資料並記入試用紀錄，**不得勾選或保存任何決策**；重設操作資料可回到起點。
- `validate_html.py` 會檢查每張 `data-need="1"` 卡片都有 `data-demo` 按鈕，缺了就 FAIL。

## 狀態與資料邊界

操作資料與決策回覆使用不同儲存鍵或不同資料表，且重設操作體驗不得清除決策。建議狀態模型：

```text
practice: 操作體驗產生的示範資料
trial: 試用過哪些方案及目前測試設定
draft: 尚未保存的選項、四態與補充
saved: 最後一次成功保存的意見
```

- 匯出必須同時列出已保存、未表態及未保存草稿；草稿不可混入已核准清單。
- 匯入續評不得丟失草稿、已保存意見或試用紀錄，也不得因匯入而自動保存。
- 更換 `DOC_ID` 或既有題目 ID 會讓瀏覽器儲存對不上。修既有確認台時保持識別碼穩定。
- 涉及真實個資的操作只用欄位結構或明確的虛構測試資料；公開／唯讀畫面在產生資料時排除敏感欄位，不能只靠 CSS 隱藏。

## 施工順序

1. 從使用者的實際工作列出 2～5 條主要任務，砍掉以資料表名稱堆出的多餘頁面。
2. 先做能走完的主要流程及錯誤流程，再寫八節說明與決策。
3. 每一題接上「▶ 試給我看」，會改變操作差異的選項接到「試用此做法」；試用後仍維持未回答。
4. 加入逐題保存、未保存提示、JSON／Markdown 匯出、匯入續評及手動複製退路。
5. 實際驗證寬螢幕、窄螢幕、鍵盤、重開保存與重設隔離。

## 驗收

- 操作體驗與決策確認可在同一份 HTML 切換，切換時不丟失進度。
- 至少一條核心工作可從開始做到完成；取消、缺欄與儲存失敗不產生半筆資料。
- 試用不會改變草稿或已保存意見。
- 每一題都有「▶ 試給我看」，而且實際按過：畫面真的變了、泡泡說得出在看什麼。
- 草稿在輸入當下可辨識，只有保存成功才移入已保存。
- 未回答、未表態及未保存草稿均不呈現成核准。
- 匯出文字能讓另一個代理清楚分辨不要、要改、待議、同意、未表態與未保存草稿。
- 關閉 JavaScript 時仍讀得到八節內容及主要操作說明。
- `scripts/validate_html.py` 與真實瀏覽器寬／窄畫面驗收均通過。
