# 自帶元件庫 · 索引

> **這個技能啟動後，動手寫任何 HTML／介面之前，先讀這一個檔案。**
> 讀完就知道手上已經有什麼，不要從頭刻。找不到相符的再自己寫。

## 這是什麼

從使用者的「軟體資料庫」摘出來的**視覺與介面部分**，**原封不動複製**進技能裡。
每一條都在真實系統上跑過。目的只有一個：**換一台電腦、換一個人，都不必重新找元件或重建框架。**

- `ui/` — 視覺基底（配色、字級、間距、規格預覽）
- `components/` — 可拆用的介面元件與版型
- `tools/` — 支撐這個技能各任務類型的腳本（確認台匯出、舊 Excel/VBA 現代化、敏感資料去識別化、技能自檢）
- `principles/` — 這些元件背後的做法原則（**照著做，不要用預設方式覆蓋**）

各條目的 `說明.md` 都有一節「**移植點**」，寫明哪幾行是原專案專屬、要換掉。**先讀它再複製。**

## 兩軌產出各自吃哪些

**軌道 B｜協作確認台**（固定視覺，不隨案調）
- 視覺一律用 `F-UI-001`。**token 值已經預先烤進 `assets/review-console-template.html`，直接用骨架即可**，不必再複製 CSS。
- 需要跳題／搜尋時抄 `F-UI-002`。
- 匯出段落照 `F-AI-007` 的做法，把「什麼樣的產出會被退」一起寫進去。

**軌道 A｜客戶展示頁**（視覺隨案調，模仿被展示的系統）
- **不要套 `F-UI-001`** ——套了客戶就認不出那是自己的系統。
- 但**版面骨架、元件狀態、互動行為照抄** `components/` 底下對應的條目，只換配色與字體。
- 要哪種畫面就找哪一條：後台版型 `F-UI-003`、編輯頁 `F-UI-005`、看板 `F-UI-007`、公開展示 `F-UI-010`、表單 `F-FORM-008`。

## 已知落差（複製前要知道）

1. **`F-UI-001` 原始版只有亮色。** 說明檔的「已知限制」寫明沒有暗色 token。
   但本技能第五節要求深淺色跟隨系統——**`assets/review-console-template.html` 裡的那份已經補了暗色**，
   要暗色時以骨架裡的為準，不要退回原始 `tokens.css`。
2. **`app.css` 的 class 命名跟原專案 HTML 結構耦合**，不是通用 utility framework。**只抄需要的元件，不要整份搬。**
3. **多數 `components/` 條目是 React／HTMX／Streamlit**，本技能的兩軌產出是**單檔、零外部相依的純 HTML**。
   複製時要抄的是**版面結構、狀態設計、互動邏輯**，不是框架程式碼本身。

## 這裡沒有的東西

收的是**視覺與介面**，加上**支撐本技能既有任務類型的腳本**（舊 Excel/VBA 現代化、敏感資料腳本中介、技能自檢）。
**後端、資料庫、部署、匯入對帳、報表、排程、外部整合一概沒收**——
那些是「做完整系統」的零件，不是「用可視化跟 AI 協作」的零件，硬塞進來只會讓技能肥大且跟正本分岔。

需要那些時，去使用者本機的軟體資料庫：
`03_獨立軟體與網頁專案/軟體資料庫/INDEX.md`（65 條功能、55 條知能）。
**該路徑只在使用者自己的機器上存在**；在別台機器上就當作沒有，照樣可以只用這裡的東西完成工作。

## 正本與分岔

正本是軟體資料庫，這裡是**摘錄快照**。
在這裡改了東西不會回流正本；要沉澱回去請走 `software-library` 技能的收錄流程。
