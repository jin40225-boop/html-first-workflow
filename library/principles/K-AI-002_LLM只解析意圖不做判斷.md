# LLM 只解析意圖，不做判斷

## 問題

要不要讓 AI 參與處理業務資料？

不用，使用者得自己在一堆選單和欄位裡摸索。
全用，AI 會產生幻覺——它會「算」出一個看起來很合理但錯誤的統計數字，而且錯得毫無徵兆。

在社福、財務、醫療這類**錯了有實際後果**的領域，第二種比第一種糟得多。

## 原則

**把「聽懂人話」和「執行運算」拆開。**

- **LLM 負責**：把「幫我比對這兩份名單有沒有重複」翻譯成 `{ task_type: "compare", mode: "duplicate_cases", file_a: ..., file_b: ... }`
- **確定性程式負責**：真的去跑那個比對，回傳精確結果

原始碼裡的原話（`private-data-workbench` 工作台首頁）：

> 查找、核對、統計與去識別化皆由本地 Python 程式（Pandas, DuckDB）**100% 精準執行，
> LLM 絕不參與查核判斷**，防止產生幻覺或個資外流。

以及自然語言輸入框旁邊那句：

> 本地 LLM 會將其解析成任務 JSON，但**實際運作仍會由本機程式執行**。

## 為什麼這個分法是對的

| | LLM 擅長 | 確定性程式擅長 |
|---|---|---|
| 聽懂含糊的人話 | ✅ | ❌ |
| 從自由文字抓出參數 | ✅ | ⚠️ 要寫很多正則 |
| 精確計數 | ❌ **會編** | ✅ |
| 比對兩份表格 | ❌ **會漏會編** | ✅ |
| 判斷兩筆是不是同一人 | ⚠️ 沒有依據 | ✅ 有明確規則與門檻 |
| 可重現 | ❌ 同樣問題兩種答案 | ✅ |
| 可稽核 | ❌ 說不出為什麼 | ✅ 邏輯攤在程式裡 |

**LLM 猜錯參數，使用者一眼看得出來**（「我要比對 A 和 B，它怎麼填成 A 和 C」）。
**LLM 算錯數字，沒有人看得出來**——這才是真正的風險。

## 做法

### 一、解析結果要攤開來給使用者看

```python
st.markdown("### 📋 解析出的任務結構 (JSON)")
st.json(task.dict())
```

不要「使用者打一句話 → 直接跑」。中間把解析出的 JSON 顯示出來，讓人確認參數對不對。
**這同時是 `K-GOV-001 預覽與提交分離` 在 AI 場景的版本。**

### 二、解析完只給「建議」，不自動執行

```python
page_mapping = { "compare": "3_資料核對", "anonymize": "4_個資隱匿", ... }
st.info(f"💡 系統建議：請點擊左側選單的 **{target_page}** 頁面來執行此任務。")
```

引導而不代勞。使用者還是走正常的功能頁面，那裡有完整的參數與確認流程。

### 三、LLM 掛掉要能降級，不能整個不能用

```python
if is_available:
    st.success(f"本地 {runner} 服務：連線成功")
else:
    st.error(f"本地 {runner} 服務：未偵測到服務 (已降級為手動表單)")
```

以及解析失敗時：

```python
except Exception as e:
    st.error(f"任務解析失敗：{e}")
    st.info("系統已自動改用手動操作模式，請在左側選單選擇功能進行手動核對。")
```

**LLM 是加分項不是必需品。** 服務沒開、模型掛了、解析失敗——核心功能都必須照常可用。
（這也是 `K-RESIL-001 失敗要留痕，但不擋主流程` 的一個實例。）

### 四、把「誰做了什麼」寫進報告

`F-AI-004` 的合規報告有這兩項：

```
12. 本次處理是否使用 LLM：否 (採純本地確定性規則程式處理)
14. 使用之本地 LLM 模型名稱：無
```

**事後要答得出「這個結果是程式算的還是 AI 講的」。** 這在需要對外舉證時是決定性的差別。

## 什麼時候可以讓 LLM 判斷

不是所有場合都要這麼嚴。判準是：**這個判斷錯了，有沒有人會發現？**

- 摘要一段會議記錄 → 錯了人看得出來 → 可以讓 LLM 做
- 從一段文字抓出日期與人名 → 錯了會被下一步的驗證擋下 → 可以，但要驗
- 算出「本月新案 47 件」→ **錯了沒人會發現** → 絕對不行

還有一條：**只要輸出會進入正式報表或對外文件，就不要讓 LLM 產生數字。**
