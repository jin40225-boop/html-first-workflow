# 結果鎖定與呈現分離

## 問題

抽選、輪派、配對或名額分配常用動畫增加可理解性；但如果每次播放動畫都在瀏覽器重新亂數，同一筆「正式結果」會隨重播、重新整理或換裝置而改變。

這不只是視覺問題。當結果會影響人員、名額或後續紀錄時，動畫就意外成了決策來源，沒有人能說清楚哪一次才算數。

## 原則

**先決定並保存結果，再播放結果。**

結果生成是一次明確的資料異動；動畫、燈箱與重播都是讀取既定結果的呈現行為。若需要改變結果，必須另設「重抽／重排」動作，重新進行授權與稽核，而不是把它藏在同一個播放按鈕裡。

## 做法

1. 由伺服器產生結果、序號與必要的呈現資料，並在同一流程保存。
2. 前端開啟燈箱時，只讀取已保存的結果；重播只重啟動畫，不呼叫產生新結果的 API。
3. 開始操作若已有結果，直接回傳原結果，避免多個視窗或重送請求各自建立不同答案。
4. 重抽採獨立 API 與明確文案，重新驗證寫入權限後才建立新序號與新結果；舊結果應保留足以追溯的紀錄。
5. 動畫可採 SVG、卡片或其他效果，但需保留減少動態效果的替代呈現，不能讓動態效果影響資料本身。

## 判準

- **可重播**：同一序號、同一結果、沒有新資料寫入。
- **可重抽**：另一個明確異動，具重新授權與可追溯新序號。
- **不可接受**：用前端亂數直接決定正式人選，或讓播放按鈕同時兼作重抽。

## 為什麼值得寫下來

這條界線讓互動感與資料可信度可以同時成立：使用者能反覆觀看過程，管理者仍能明確指出正式結果及其產生時間。它也降低多裝置、多分頁和網路重送造成結果漂移的風險。

## 適用範圍

適合抽選、排班輪派、候補遞補、名額分配、抽題與其他「結果會影響後續權益或工作安排」的互動流程；不適用於純娛樂且不保存、不影響任何後續決策的即時動畫。
