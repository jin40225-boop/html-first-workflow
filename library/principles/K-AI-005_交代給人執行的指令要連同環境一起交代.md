# 交代給人執行的指令，要連同環境一起交代

## 問題

有些步驟 AI 不能代跑——需要密碼、需要瀏覽器授權、或那本來就是人該按的核准。
這時 AI 會給出幾行指令請使用者自己執行。

一次資料庫變更的交付裡，給出的是這樣三行：

```
npx supabase link --project-ref xxxx
npx supabase migration list --linked
npx supabase db push
```

使用者的回應是：

> 「這個要在哪裡跑？我希望妳後續都要標明、說明清楚步驟與網址。」

而這個問題完全合理，因為那次的實際環境是：

- 程式**不在**他當時打開的工作資料夾，在另一顆磁碟
- 版控的根目錄還比程式資料夾**再高一層**（`.github`、專案規則都在上層），
  但要跑那些指令得在**下層**，因為設定檔在那裡
- 第一行其實**可以跳過**——專案早就連結過了
- 而真正缺的那一步（登入）我沒寫，因為我用「找不到憑證檔」判斷成沒登入，
  實際上該版 CLI 把憑證存在作業系統的認證管理員裡，**判斷方法本身是錯的**

三行指令都對，但照著跑會跑錯地方、少一步、多一步。

## 原則

**指令只是動作。要讓人執行得起來，必須連同「在哪裡、用什麼、會被問什麼」一起交代。**

判準：**對方不需要回頭問任何一句，就能開始跑。**
如果他得先問「這在哪跑」，那份交代就是不完整的。

## 做法

每一段要別人親自執行的指令，前面先給這幾行：

```
資料夾：<絕對路徑>   ← 若與對方當前開啟的不同，明確標出來
終端機：PowerShell / Bash / …
相關網址：<控制台／後台／正式站的完整 URL>
```

再加上：

**一、會被問什麼。** 登入、資料庫密碼、瀏覽器授權跳窗——事先講，
並附上「忘記密碼去哪裡重設」的網址。人在半途被問一個沒預期的問題，就會停下來。

**二、前置狀態：我已經先查過什麼，哪幾步可以跳過。**
不要讓對方用執行結果去反推環境狀態。同時要注意——**查證方法本身要先被驗證**
（見 [驗證方法本身要先被驗證](../驗證與檢查/驗證方法本身要先被驗證.md)），
上面那個「找不到憑證檔就判定沒登入」正是反例。

**三、一個區塊一條指令。** 不要把多行擠在同一個程式碼區塊。
方便一鍵複製，也讓人看得出中間該停下來確認的地方在哪。

**四、跑完要回報什麼、下一步是什麼。**
例如「把 `migration list` 的輸出貼回來，確認只有兩支待推我才繼續」——
這讓手動步驟變成有交接點的流程，而不是丟出去就沒下文。

**五、預期輸出長什麼樣，以及什麼情況要停下來。**

> 應該只會顯示兩支待推。如果冒出更多，先停下來把輸出貼給我——
> 那代表正式庫比我以為的還舊，一次推上去會連帶套用我沒檢查過的舊變更。

這一句比指令本身更有價值：它把「照做」變成「照做並且看得懂」。

## 為什麼值得寫下來

AI 交付的最後一哩幾乎都落在人手上——部署、核准、輸入密碼、按下公開。
**那一哩失敗，前面做多好都不算交付。**

而失敗的原因通常不是指令錯，是**環境沒對齊**：跑錯資料夾、少了登入、
或指令要在子目錄跑而版控在上層。這些對寫指令的人是背景知識，對執行的人是隱形的。

這條與「預覽網址要標明資料夾／分支／commit」是同一個原則的兩個面向：
**不要讓人自己去推斷環境狀態，讓輸出直接把狀態講出來。**
