# 交給不懂電腦的人用

## 問題

系統寫好了，功能都對，但使用者是社工、行政、志工——不是工程師。
他們不會看 log、不會下指令、不知道什麼是埠、遇到問題只會說「壞掉了」。

**系統能不能用，取決於最不懂電腦的那個人能不能用。**

## 原則

### 一、入口只能有一個

分享資料夾裡放一堆 `.bat` `.ps1` `.exe`，使用者一定會點錯。
只留一個：`00_請點我開啟XXX.lnk`。其他全部收進子資料夾。

命名用「請點我」這種白話，不用「啟動器」「Launcher」。

### 二、把會出錯的地方先擋掉，而不是寫在說明書裡

說明書沒有人看。所有能自動處理的都自動處理：

- 埠被舊程序佔用 → 自己清掉，而且**真的等它釋放**再啟動
- 資料夾不存在 → 自己建
- 相依套件沒裝 → 明確說「請先安裝 Node.js」，不要丟原始錯誤
- 找不到選用的來源檔 → 記一筆 log 正常結束，**不要讓整個系統啟動失敗**

### 三、視窗上的警語比程式碼重要

```
[注意] 這個黑視窗就是系統主機，請勿關閉。
[注意] 啟動約需 10 秒，看到 "Server is running" 後再開瀏覽器。
```

第一行防止使用者「整理桌面」時把主機關掉。
第二行防止太早開瀏覽器看到錯誤然後以為壞了。

**這兩行避免掉的求助次數，超過腳本裡任何一段程式碼。**

### 四、出錯時視窗不能消失

```powershell
Read-Host '伺服器已停止，按 Enter 關閉視窗'
```

錯誤訊息一閃而過等於沒有。停在那裡，使用者才能截圖傳給你。

同理：無視窗的打包程式一定要把 stdout/stderr 重導到日誌檔，否則「雙擊沒反應」完全無從查起。

### 五、讓系統自己說它是什麼版本

不要讓使用者（或 AI）去猜現在跑的是哪一版。

- 打包時把版本資訊燒進產物
- 開一個不需權限的端點吐出來
- 畫面上放一個常駐徽章
- 靜態檔案掛版本號做快取破壞

**核心規則：不要讓人幫使用者找版本；讓系統自己顯示版本。**

### 六、狀態要寫成人看得懂的檔案

排程、備份這類「在背景默默跑」的東西，要留一份人看得懂的狀態檔：

```
最後檢查時間：2026-06-17 09:12:03
今日備份：...\..._每日備份_20260617.xlsx
備份規則：每天第一次啟動系統時建立當日備份；同一天重複啟動不覆蓋。
```

使用者想確認「到底有沒有在跑」時自己開這個檔就知道，**不用來問你，也不用看 log**。

### 七、部署腳本要處理「現場停不下來」

複製執行檔到分享槽時，一定會遇到有人正開著。
腳本要把結果分成三類：**成功 / 被佔用 / 失敗**，並提示「請通知對方關閉後重跑」。

不能假設可以停機。

### 八、輔助功能失敗不能拖垮主功能

備份、日誌、統計這類輔助功能，一律包 try/catch，**錯誤只記不拋**。
但也不能靜默——訊息一定要進 log。

## 為什麼這些值得寫下來

因為它們全部都是**踩過才知道的**，而且每一條都很便宜。

多寫兩行警語、多包一層 try/catch、多留一個狀態檔——加起來不到半天工，
換來的是使用者不用打電話問你，而你不用在下班時間遠端連線。
