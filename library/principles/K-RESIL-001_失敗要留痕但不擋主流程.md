# 失敗要留痕，但不擋主流程

## 問題

一個統計查詢失敗，整頁 500——使用者連還能用的部分都看不到。
一支備份腳本找不到來源檔，回傳非零結束碼，整個系統啟動失敗。
一個 PDF 改名失敗，導致使用者的「確認接案」動作被拒絕。

**輔助功能壞掉，主功能陪葬。**

## 原則

先分清楚哪些是**主流程**、哪些是**輔助**。

- **主流程**：使用者當下要做的那件事（存檔、送出、查詢）
- **輔助**：讓那件事更完整的東西（改檔名、寫統計、備份、發通知）

**輔助失敗絕對不能讓主流程失敗。但輔助失敗一定要留下痕跡。**

兩件事都要做到。只做前面是掩蓋問題，只做後面是本末倒置。

## 做法

### 一、呈現層的每個資料來源獨立包起來

```python
def _safe_count(sql, params=()):
    try:
        return fetch_one(sql, params)["c"]
    except Exception:
        return 0
```

儀表板上七張卡片，一張查詢失敗回 0，其餘六張照常顯示。
**不要讓一個統計拖垮整頁。**

模組註解直說：「避免儀表板炸頁」。

### 二、模板過濾器永不拋例外

```python
def roc_date(value):
    try:
        ...轉民國日期...
    except Exception:
        return value        # ← 轉不了就原樣回傳
```

模板渲染失敗的代價是整頁 500。**一個日期格式化函式不值得讓整頁掛掉。**

### 三、明確標示「這裡的失敗是可以吞的」

```python
try:
    rename_after_import(record)
except Exception:
    pass          # 檔名標記是輔助，不能擋住業務動作完成
```

`except: pass` 通常是壞味道——**除非你在旁邊寫清楚為什麼**。
沒有註解的 `pass` 是偷懶，有註解的 `pass` 是決策。

### 四、外部資源失敗要退回內建版本

```
月報 Word 樣板：
  設了路徑但檔案不在 → 用內建版面 + 警示訊息
  檔案在但開檔失敗   → catch 之後改用內建版面【重產一次】+ 改寫警示
```

**「樣板壞檔不可拖垮整份月報。」**

注意第二層——不只是 catch，是 catch 之後**真的再做一次**。只 catch 不重做等於使用者拿不到報表。

### 五、選用性的前置工作，失敗算「略過」不算「錯誤」

```powershell
if (-not (Test-Path $SourceExcel)) {
  Write-BackupLog "略過：找不到正式 Excel：$SourceExcel"
  exit 0                      # ← 是 0 不是 1
}
```

網路磁碟沒連上、來源檔被搬走——**這不該讓系統啟動失敗**。
記一筆 log，正常結束，讓主流程繼續。

### 六、留痕的地方要讓人找得到

吞掉的錯誤如果只寫進沒人看的地方，等於沒留。

- 無視窗程式 → 重導到 `logs/startup_時間_PID.log`，保留最近幾份
- 背景排程 → 寫狀態檔，人看得懂的格式
- 使用者當下能修的 → 直接顯示警示訊息（例如「樣板檔案不存在，已使用內建版面」）

## 反面：什麼時候應該讓它爆

**寫入路徑不適用這一條。**

存檔失敗就要讓使用者知道存檔失敗。假裝成功、事後靠 log 補救，是最糟的做法——
使用者會以為資料存好了。

判準：**這個失敗會不會讓使用者對系統狀態產生錯誤認知？**
會 → 一定要報。不會 → 可以吞，但要留痕。
