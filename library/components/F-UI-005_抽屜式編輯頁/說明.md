# 抽屜式編輯頁

## 這個功能幫我做什麼

把「清單 → 點進去 → 編輯頁 → 存檔 → 回清單」這個四步跳頁，**壓成「在清單上滑出一個抽屜」**。

487 行的模板，是資料庫裡最大的單一元件。它取代了原本獨立的編輯頁——
舊網址現在是 301 導回清單並自動展開抽屜，**獨立編輯頁整個廢掉**。

## 為什麼值得這樣改

現場的工作方式是「一次處理一批案子」。跳頁的成本不是那 0.5 秒，是**每次回到清單都要重新找剛才看到哪**。

抽屜讓清單一直在，關掉就回到原位。

## 五個核心設計

### 1. 三色欄位標示

```python
def field_class(field, case, auto_filled, initial_pending):
    if field in auto_filled:        return "field-auto-filled"    # 綠：機器填的
    if field in missing_required:   return "field-required-empty" # 紅：必填未填
    if initial_pending:             return "field-needs-manual"   # 黃：待人工確認
```

**優先序是刻意的**：綠 > 紅 > 黃。
「這格是 PDF 自動填的」比「這格沒填」更重要——因為使用者要知道**哪些值不是他打的、需要核對**。

### 2. 破壞性動作全部走原生 `<dialog>`，且放在主表單之外

結案、退案、轉外轄、併案、分級異動、轉案、重啟——七個破壞性動作，各自一個 modal。

```html
<form id="main-form">…一般欄位…</form>

<dialog id="dlg-close">
  <form hx-post="/cases/123/drawer/save">
    <input type="hidden" name="mode" value="結案">
    <textarea name="close_reason" required></textarea>
  </form>
</dialog>
```

**兩個關鍵**：

- **放在主表單之外**——HTML 不允許 form 巢狀，放在裡面會靜默壞掉
- **每個 modal 各自 POST 到同一個端點**，用 hidden `mode` 區分 → 後端一個入口分派（見 `F-FORM-005` 的處理方式分流）

用原生 `<dialog>` 而不是自刻 modal：**焦點管理、Esc 關閉、背景遮罩瀏覽器都幫你做好了**。

### 3. 儲存後整個抽屜換回來

```html
hx-post="/cases/123/drawer/save"  hx-swap="outerHTML"
```

不論成功或失敗，後端都回傳**完整的抽屜 HTML**。

好處：錯誤訊息、更新後的欄位標示、變動後的可用動作，全部一次到位——
不用在前端維護「存檔後該更新哪些地方」的邏輯。

### 4. 唯讀狀態由兩個來源合成

```python
status_readonly = case_status in ("已結案","退案","轉外轄")
access_readonly = 非主責但有歷程紀錄的檢視者
can_reopen      = status_readonly and not access_readonly
```

**「不能編輯」有兩種原因，處理方式不同**：
案件已結案 → 可以「重啟」；不是你的案 → 只能看。

合成成一個布林會做不出這個區分。

### 5. 三層摺疊，但預設展開常用的三組

八組欄位用 `<details>` 摺疊，**基本／聯絡地址／服務三組預設展開**——
那是九成情況下要看的。其餘收起來。

進度條由案件狀態映射：待認領/待確認=第1步、待補齊/在案處遇中=第2步、已結案/退案/轉外轄=第3步。

## 一個 HTMX 陷阱

```python
def _redirect_htmx_aware(url):
    if request.headers.get("HX-Request"):
        return "", 204, {"HX-Redirect": url}   # ← 不是 302
    return redirect(url)
```

**HTMX 請求不能回 302**——瀏覽器會跟隨轉址，把整頁 HTML 塞進抽屜，變成「頁中頁」。
要回 204 + `HX-Redirect` 標頭讓 HTMX 自己導。

## 焦點陷阱在 `F-UI-002` 的 JS 裡

`DcmsWarm.openDrawer/closeDrawer` 做了完整的 focus trap：記住開啟者、Tab/Shift+Tab 循環、
Esc 關閉、關閉後把焦點還回去。**無障礙不是加分項，是抽屜這種元件的必要條件**——
不然鍵盤使用者一按 Tab 就跑到抽屜後面的頁面去了。

## 移植點

| 位置 | 要改的 |
|---|---|
| 八組欄位與其內容 | **整段換成你的欄位** |
| `field_class` 的三色判定 | 三色的概念可留，判定條件換你的 |
| 七個破壞性動作 modal | 換成你的動作 |
| 狀態 → 進度條的映射 | 換成你的狀態機 |
| `build_case_context` 的 20+ context | 換成你要傳的 |

**可以整段照抄的**：`<dialog>` 放在主表單外 + hidden mode 的結構、`hx-swap="outerHTML"` 整塊換回、唯讀雙來源合成、`_redirect_htmx_aware`、`history.replaceState` 關閉時清掉網址參數。

## 相依套件

HTMX（局部換 HTML）。`<dialog>` 是瀏覽器原生。

## 已知限制

- **487 行的單一模板**，改起來要小心。移植時建議照欄位群組拆成多個 include（原專案的欄位群組已經是分開的檔案）。
- 抽屜寬度固定，超寬螢幕會浪費空間。
- 同時只能開一個抽屜。要並排比較兩個案件做不到。
