# 內頁全域公告跑馬燈

## 這個功能幫我做什麼

讓建立者在既有貼文裡勾選一則公告，公告就能顯示在所有已取得內部編輯權的工作頁頁首；
公開首頁維持排除。系統會依有效期間、緊急程度與更新時間挑出最多三則，並提供暫停、
滑鼠停留、減少動態效果及返回原貼文。

它不是只有動畫元件：完整功能同時包含**貼文資料契約、授權 API、排程／排序、跨頁刷新與可及性**。

## 技術線

```text
既有貼文 modules JSON
  -> normalizeModules：80 字、層級、速度、台灣時間轉 ISO
  -> GET /api/marquee：編輯工作階段、未封存／未刪除、有效期間、排序、最多三則
  -> GlobalMarquee：首頁排除、每分鐘刷新、事件刷新、暫停、reduced-motion、返回原貼文
```

### 為什麼沿用貼文，不另建公告表

| 方案 | 優點 | 代價 |
|---|---|---|
| 沿用貼文 `modules` | 跟隨既有建立、編輯、封存、回收、板塊與授權生命週期 | 查詢時要解析 JSON |
| 另建公告表 | 欄位與查詢直觀 | 會多出第二套建立入口、授權、封存與原文連結 |

本案例的跑馬燈本質是「一篇貼文的選填呈現方式」，因此沿用貼文生命週期可避免兩份真相。

## 核心手法

### 一、API 與元件各自守一次顯示範圍

API 先驗證有效編輯工作階段；元件再檢查 `editor` 與 `pathname === "/"`。
前者守資料可見性，後者守產品顯示範圍，兩者不能互相取代。

### 二、伺服器決定有效、排序與數量

後端先排除封存／刪除貼文與尚未開始／已結束的公告，再以緊急、重要、一般排序；同級以
更新時間排序，最後 `slice(0, 3)`。因此所有內頁看到同一組結果，前端不各自猜測。

### 三、本地時間先正規化，舊錯誤只做精準相容

`datetime-local` 沒有時區。新資料在寫入前轉 ISO；伺服器仍把舊式無時區輸入明確視為
台灣 `+08:00`。版本 15 的歷史錯誤只在開始時間與建立／更新時間加八小時相符、且落在
15 分鐘容差內才回推，不把所有未來排程一起提前。

### 四、動畫不是唯一呈現

一般模式可暫停、點擊暫停與滑鼠停留；使用者偏好減少動態效果時改成靜態可捲動內容。
公告訊息保留語意標籤與返回原貼文連結。

## 移植點

| 檔案／位置 | 要換掉的內容 | 怎麼改 |
|---|---|---|
| `route.ts` 的 `getDb`、`boardPosts`、`hasEditorSession` | 專案資料庫與授權 | 改成新系統的貼文查詢與內部工作階段；匿名仍須 fail closed |
| `route.ts` 的 `BOARD_META` | 板塊到網址的對照 | 換成新系統的頁面路由，或直接保存原文 href |
| `post-modules.ts` 的 `PostModules` | 整份貼文模組契約 | 若新系統沒有其他模組，只保留 marquee 欄位；仍保留長度、enum 與日期正規化 |
| `GlobalMarquee.tsx` 的 `editor` 與 `/` | 內部身分與公開首頁 | 依新專案的 auth shell 與公開入口調整；不要只靠 CSS 隱藏 |
| `GlobalMarquee.tsx` 的 60 秒輪詢 | 更新頻率 | 依流量與即時性調整；建立／更新成功後仍建議發送 refresh 事件 |
| CSS class 與 `react-fast-marquee` | 外觀與動畫 | 本條未複製共享樣式表；依新設計系統補樣式並保留 reduced-motion |

可直接沿用的是：雙層範圍守門、伺服器排序／限量、台灣時間正規化、精準舊資料相容、
事件＋輪詢刷新，以及動畫／靜態兩條可及性路徑。

## 已知限制

- `route.ts` 綁定原專案的 Drizzle schema、板塊設定與編輯工作階段，不能整檔貼上就上線。
- `post-modules.ts` 同時包含其他貼文模組，移植時可依移植點裁切；資料庫保存的是已驗證原檔，不預先改寫。
- 建立／編輯 UI 位於已收錄的 `F-UI-008 模組化貼文與收合式功能設定` 之後續版本，本條不重複複製整個大型編輯器。
- 共用 CSS 未收錄；功能邏輯完整但外觀需接新專案設計系統。
- 正式版本、網址與線上狀態是 2026-08-13 的驗收證據，不代表未來仍是最新部署。
