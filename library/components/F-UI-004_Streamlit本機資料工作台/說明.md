# Streamlit 本機資料工作台

## 這個功能幫我做什麼

**用 Python 直接寫出一個給自己用的資料處理介面**，不用碰 HTML/CSS/JS、不用起前後端、不用部署。

這是「內部工具」的最短路徑：你已經有一堆 Python 腳本在跑資料，但每次都要開終端機、記參數、改路徑。
Streamlit 讓你在**兩百行內**把那些腳本包成一個有拖放上傳、下拉選單、進度條、圖表的網頁介面。

原始專案是一個**本機隱私資料查核工作台**——匯入、搜尋、比對、去識別化、統計、安全輸出，七個頁面。

## 技術線

```
app/main.py            首頁：系統狀態 + 自然語言入口 + 使用指南
app/pages/
  1_資料匯入.py          拖放檔案 → DuckDB
  2_關鍵字查找.py         跨檔搜尋
  3_資料核對.py          兩表比對（呼叫 F-IMP-004）
  4_個資隱匿.py          去識別化（呼叫 F-AI-004）
  5_統計計算.py          彙總統計
  6_輸出給雲端AI.py       安全匯出 + 合規報告
  7_模型與安全檢查.py      環境稽核
scripts/*.py           所有實際運算，UI 只是殼
```

**Streamlit 的多頁機制就是「在 `pages/` 底下放檔案」**，檔名前綴數字決定側欄順序。沒有路由設定檔。

## 四個核心手法

### 1. UI 只是殼，運算全在 `scripts/`

```python
from scripts.call_local_llm import check_llm_available, parse_task_json, ...
from scripts.audit_environment import audit_all
```

每個頁面都只做三件事：收參數 → 呼叫 `scripts/` 裡的函式 → 顯示結果。

**這個分層是刻意的**：同一批函式可以被 UI 用、被 CLI 用、被測試用。
UI 壞掉不影響核心功能，換掉 Streamlit 也只要重寫殼。

### 2. 側邊欄常駐系統狀態，開啟就看得到

```python
with st.sidebar:
    audit_res = audit_all()
    if audit_res.overall_status == "critical":  st.error("🔴 安全警告：環境有嚴重安全隱憂！")
    elif audit_res.overall_status == "warning": st.warning("🟡 發現潛在風險！")
    else:                                        st.success("🟢 系統安全評級：安全無虞")
```

**每次載入頁面都重跑一次稽核**。使用者不用去哪裡按「檢查」——狀態就在眼前。

這呼應 `K-OPS-001` 的「讓系統自己說它是什麼狀態」，只是對象從版本換成安全評級。

### 3. 外部服務不可用就降級，不是報錯

```python
is_available = check_llm_available(runner)
if is_available:
    st.success(f"本地 {runner} 服務：連線成功")
    models = get_available_models(runner)
    ...
else:
    st.error(f"本地 {runner} 服務：未偵測到服務 (已降級為手動表單)")
```

括號裡那句「**已降級為手動表單**」是關鍵——它同時告訴使用者「壞了」和「還能怎麼用」。

解析失敗時同樣處理：

```python
except Exception as e:
    st.error(f"任務解析失敗：{e}")
    st.info("系統已自動改用手動操作模式，請在左側選單選擇功能進行手動核對。")
```

### 4. 首頁三張卡講清楚「這個系統的立場」

```
🔍 確定性資料處理    LLM 絕不參與查核判斷，防止產生幻覺或個資外流
🛑 嚴格禁用中國 AI   全面封鎖且絕不下載、載入、使用或 Fallback
🌥️ 雲端傳輸安全閘    強制殘留掃描與稽核，產生 18 項檢查點報告
```

**內部工具的首頁不該是空的。** 用三張卡把「這個工具保證什麼」寫在最顯眼的地方——
新同事第一次打開就知道規則，不用讀文件。

## 樣式：Streamlit 也可以不醜

原專案用一段 `st.markdown(..., unsafe_allow_html=True)` 注入 CSS：深色底、漸層標題、卡片陰影。

```css
h1 { background: linear-gradient(135deg,#38bdf8,#818cf8);
     -webkit-background-clip: text; -webkit-text-fill-color: transparent; }
.card { background:#1e293b; border-radius:12px; padding:24px; border:1px solid #334155; }
```

**注意這套配色（深藍科技感）與 `F-UI-001 暖色設計 token` 是完全不同的方向**——
那套是給長時間值班的社工看的暖米大字，這套是給自己用的工具。**使用者不同，方向就該不同。**

## 移植點

| 位置 | 要改的 |
|---|---|
| `app/pages/*.py` | 換成你的功能頁。**檔名前綴數字 = 側欄順序** |
| `main.py` 第 20–62 行 CSS | 換成你的配色，或整段拿掉用 Streamlit 預設 |
| `main.py` 三張卡 | 換成你的系統立場 |
| `main.py` 側欄稽核 | 換成你的健康檢查 |
| `page_mapping` | 任務類型 → 頁面名稱的對照 |
| `import_files.py` / `build_index.py` | 匯入與索引邏輯 |

**可以整段照抄的**：`pages/` 多頁結構、側欄常駐狀態、`st.session_state` 初始化模式、外部服務降級的三段式（成功／失敗／例外）、「UI 只是殼」的分層。

## 已知限制

- **每次互動都重跑整個腳本**（Streamlit 的執行模型）。要保留狀態必須用 `st.session_state`，重運算要用 `@st.cache_data`。原專案的頁面都很輕所以沒問題，跑大資料時要注意。
- **沒有多使用者概念**。`st.session_state` 是每個瀏覽器分頁一份，但檔案系統是共用的。這是單人工具，不是多人系統。
- 沒有驗證。跑在 localhost 才安全，不要開到區網。
- 版面客製化程度有限。要精細控制版面就不該用 Streamlit。
