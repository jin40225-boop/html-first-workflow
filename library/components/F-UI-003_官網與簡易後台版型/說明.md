# 官網與簡易後台版型

## 這個功能幫我做什麼

一個**小型組織官網**的完整範本：前台展示頁 + 後台編輯介面 + 一份共用的內容資料。

解決的是小組織最實際的問題：**網站做好之後，誰來改上面的字？**

答案是：**組織自己的人，用後台改，不用碰程式碼、不用找工程師、不用重新部署。**

原始專案是一個社福協會的官網（首頁、關於、最新消息、聯絡、入會）。

## 技術線

```
store.js（單一內容真相來源）
  ├─ site      hero / about / contact / 入會說明 / footer 標語
  ├─ news[]    最新消息（日期/分類/圖示/是否發布/標題/摘要/內文）
  └─ ...
  ↓  存 localStorage（key: wd_site_content_v2）
  ↓  跨分頁同步：監聽 storage 事件
Home.jsx（前台）     ← 讀
Admin.jsx / AdminViews.jsx（後台）  ← 讀寫
  ↓
site.css（前台版型）  admin.css（後台版型）  colors_and_type.css（共用 token）
```

## 三個核心設計

### 1. 內容與程式碼分離，且內容是可編輯資料

```js
const DEFAULTS = {
  __v: 2,
  site: {
    hero:    { eyebrow, titleA, titleB, titleHl, titleC, lead },
    about:   { lead, intro, origin1, origin2, quote },
    contact: { email, line, org },
    membershipNote, footerTagline
  },
  news: [ { id, date, category, icon, published, title, excerpt, body }, ... ]
};
```

**標題被拆成 `titleA / titleB / titleHl / titleC` 四段**，因為中間那段要加強調樣式。
這種拆法很土，但它讓「改標題」這件事在後台是四個輸入框，而不是要懂 HTML。

`__v: 2` 是內容結構的版本號——之後改結構時可以據此做資料遷移。

### 2. 跨分頁即時同步

```js
/* Persists to localStorage; both the public site (index.html) and the
   admin (admin.html) read/write here. Cross-tab sync via the 'storage' event,
   so editing in the admin updates an open public-site tab live. */
```

後台改一個字，**旁邊開著的前台分頁立刻變**。

`storage` 事件是瀏覽器原生機制（同源的其他分頁改了 localStorage 就會觸發），
**不用 WebSocket、不用輪詢、不用後端**。對「編輯時想看效果」這個需求是最省的解法。

### 3. 發布開關而不是刪除

```js
{ id, date, category, icon, published: true, title, excerpt, body }
```

最新消息有 `published` 布林。要下架就切成 `false`，**不是刪掉**——寫過的東西留著，之後要參考或重新上架都還在。

## 移植點

| 檔案 | 要改的 |
|---|---|
| `store.js` 的 `DEFAULTS` | **整段換成你的內容結構與預設文案**。原檔含示範協會的實際文案，是範例不是模板 |
| `store.js` 第 7 行 `KEY` | localStorage 的鍵名 |
| `Home.jsx` | 前台版面。**分區結構（hero / about / news / contact）可以留，內容全換** |
| `Admin.jsx` / `AdminViews.jsx` | 後台表單欄位，跟著 `DEFAULTS` 改 |
| `site.css` / `admin.css` | 版型與配色 |
| `colors_and_type.css` | 這份與 `F-UI-001 暖色設計 token` **是同一套設計系統的另一個投影**，可以擇一使用 |

**可以整段照抄的**：`store.js` 的整體結構（DEFAULTS + localStorage + storage 事件同步 + `__v` 版本號）、`published` 發布開關的做法、標題拆段的技巧。

## 已知限制

- **內容存在瀏覽器的 localStorage**，所以：
  - 換一台電腦、換一個瀏覽器 → 看到的是預設內容
  - 清快取 → 編輯的內容全沒了
  - **多個人各自編輯不會同步**

  這對「一個人維護、內容不常改」的小官網夠用，但**只要有兩個人要一起維護，就必須換成後端儲存**。
  換的時候只要改 `store.js` 的讀寫實作，其餘元件不用動——這是它結構的好處。

- 沒有圖片上傳。圖片要另外處理。
- 沒有登入。後台網址知道就能改。**放到公開網域前一定要加保護。**
