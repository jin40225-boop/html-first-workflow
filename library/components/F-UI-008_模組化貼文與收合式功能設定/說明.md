# 模組化貼文與收合式功能設定

## 這個功能幫我做什麼

把公告、活動、教育訓練等不同頁面收斂成同一種貼文：

- 固定基礎模板：標題、文字、最多三個附件燈箱與留言。
- 選填模組：QR、傳閱單、接龍、具名投票、爬格子或隨機選人。
- 新增表單與編輯表單都用同一支模組設定器。
- 閱讀卡片只顯示狀態與操作，不外露建立者的名單及選項設定。
- 編輯入口收在「•••」選單，按下後才開啟燈箱，不占用平常閱讀版面。

## 技術線

```
PostModuleEditor.tsx     建立者設定：啟用模組、選名單、改投票選項
post-modules.ts          前後端共用資料契約、正規化與上限
ProtectedBoardClient.tsx 貼文閱讀卡、留言、附件、各模組操作與編輯燈箱
PostQr.tsx               將貼文內的文字或網址渲染成 QR
```

最關鍵的切法是：**資料契約獨立、設定元件獨立、閱讀卡片只消費正規化後資料。**
各頁只需要傳入板塊代號，不必為每個頁面重寫一套貼文元件。

## 核心設計

### 一、固定模板與選填功能分開

附件燈箱與留言是每篇貼文都具備的能力，不做成勾選項。QR、傳閱、投票等才是按篇啟用。
這能避免建立者每次都要重新理解基礎欄位，也不會因頁面名稱不同而產生不同資料結構。

### 二、設定只在建立與編輯視窗出現

傳閱名單、抽選名單與投票選項都屬於建立者設定；閱讀者只需要看完成進度、投票表單或抽選按鈕。
兩個介面分開後，貼文卡可以保持滿版、可掃讀，且不會把後台控制項誤當成使用內容。

### 三、用正規化函式守資料界線

`normalizeModules` 與 `normalizeAttachments` 統一處理：

- 文字長度、去空白與去重。
- 單篇最多三個附件。
- 投票最多八個選項。
- 抽選最多三人，且抽出數不得超過名單。
- 不合法或空白模組不進正式資料。

前端的表單限制只是體驗，真正資料界線仍由共用正規化函式決定。

## 移植點

| 位置 | 要改的 |
|---|---|
| `board-config.ts`（未收錄） | 換成新專案的板塊與人員名單 |
| `ProtectedBoardClient.tsx` | API 路徑、授權流程、附件上傳方式與文案 |
| `PostModuleEditor.tsx` | 可啟用模組、預設名單、投票與抽選上限 |
| `post-modules.ts` | 儲存格式、欄位上限及舊資料相容規則 |
| `PostQr.tsx` | QR 套件與下載需求 |

**可直接沿用的**：固定模板／選填模組的分層、設定燈箱、共用資料契約、名單編輯器與讀者卡片不外露設定的做法。

## 相依套件

React、Next/Vinext、`qrcode`。附件上傳與資料保存 API 需由移植專案自行接上。

## 已知限制

- `ProtectedBoardClient.tsx` 是整合元件，移植時應依新專案拆分卡片、表單與 API hook。
- 人員名單刻意不收進資料庫，需從新專案的設定檔提供。
- 本條只收前端與資料契約；傳閱／投票後端另見 F-FORM-007。
