# 舊 Excel 結構勘查器

## 這個功能幫我做什麼

把一份用了很多年、有巨集有公式的 `.xlsm` / `.xlsx`，**在不開啟 Excel、不執行巨集、不讀取任何一筆真實資料的前提下**，產出一份 Markdown 報告，說明：

- 有哪些工作表、各自幾列幾欄、多少儲存格、多少公式
- 有哪些具名範圍（named range）
- 主要輸入表的欄位配置（可跨多列表頭合併判讀）
- 資料列筆數與明細筆數的對帳統計
- 全表掃描 `#REF!` 壞掉的參照
- 遷移風險與待確認問題

**這份報告就是交給 AI 的東西。** 你不用把含個資的活頁簿丟給 AI，AI 也能完整理解這張表的結構、知道欄位怎麼排、知道哪裡有雷。

> 這是 Excel VBA 時代「欄位盤點巨集」的下一代。同一個念頭，換成不依賴 Office 的實作。

## 技術線

```
.xlsm 檔
  │  yauzl                        ← xlsx/xlsm 本質是 zip，直接拆
  ▼
xl/workbook.xml, xl/worksheets/*.xml, xl/sharedStrings.xml
  │  fast-xml-parser              ← 讀 XML，不還原成 Excel 物件
  ▼
OoxmlWorkbook { sheetNames, worksheets, definedNames, hasMacroProject }
  │  inspect_legacy_workbook.ts   ← 走訪結構、統計、產表
  ▼
legacy_excel_findings.md          ← 給 AI / 給人看的結構報告
```

### 為什麼不用 exceljs 或 SheetJS

| 需求 | 現成套件的問題 | 這個做法 |
|---|---|---|
| 讀 `.xlsm` 但不碰 VBA | 多數套件會嘗試載入或直接拒絕巨集檔 | 只讀 `xl/` 底下的 XML，偵測 `xl/vbaProject.bin` 存在與否但不解析 |
| 要看得到**公式本身**而不是計算結果 | 一般讀取偏向取值 | 每個儲存格同時保留 `value` 與 `formula` |
| 不能把整份活頁簿載進記憶體 | 大型 xlsm 吃記憶體 | 串流拆 zip，只取需要的 XML entry |
| 不能有 Office / COM 相依 | 部分方案需要裝 Excel | 純 Node，可在無 Office 的機器與伺服器上跑 |

## 輸入 → 輸出

| | |
|---|---|
| **輸入** | 一個 `.xlsx` / `.xlsm` 的絕對路徑 |
| **輸出** | 一份 Markdown 報告（見同層 `範例輸出.md`） |
| **不產生** | 任何含真實姓名、身分證、地址、電話的內容 |

## 相依套件

```json
{ "yauzl": "^2.x", "fast-xml-parser": "^4.x" }
```

兩個都是純 JS、無原生編譯、無 Office 相依。

## 移植點（要換掉的地方）

`code/ooxmlWorkbook.ts` — **通用元件，原則上一行都不用改。**
它只認 OOXML 規格，不認任何業務欄位。可以直接整份複製到新專案。

`code/inspect_legacy_workbook.ts` — **這支是報告產生器，以下要改：**

| 行 | 內容 | 怎麼改 |
|---|---|---|
| 3 | `import ... from '../apps/server/src/services/ooxmlWorkbook.js'` | 改成新專案裡 `ooxmlWorkbook.ts` 的實際相對路徑 |
| 5 | `WORKBOOK_PATH = path.resolve('D:/...xlsm')` | 換成你要勘查的檔案；建議改成 `process.argv[2]` 由命令列傳入 |
| 6–7 | `OUTPUT_DIR` / `OUTPUT_FILE` | 換成報告要放哪 |
| 64 | `inputSheetName = '發送清單 (先填此) '` | 換成你的主要輸入表名稱（**注意原值尾端有空白，舊表常見**） |
| 74–93 | 表頭讀第 3/4/5 列 | 換成你的表頭在第幾列 |
| 86–90 | `zeroBasedCol >= 20 && <= 55`、`18` 個品項欄成對 | 這是「一列裡有 N 組重複欄位」的展開邏輯，換成你的欄位配置 |
| 101–116 | 對帳統計以第 2 欄姓名判斷是否為資料列 | 換成你的關鍵欄 |
| 128 | `printSheetName`、138 `keyCells` | 換成你要抽查的第二張表與關鍵儲存格 |
| 171–179 | 遷移風險與待確認問題 | 這是**人寫的判斷**，每個專案不同，重寫 |

**通則化的做法**：把 5、6、7、64 四個常數提到檔案最上方成為 `CONFIG` 區塊，其餘保持原樣，一份新報告 20 分鐘內可以產出。

## 這個功能同時是一種做法

它不只是工具。它體現的原則是：**與 AI 協作時，交付「結構」而不是「內容」。**

結構足以讓 AI 設計欄位對照、規劃遷移、寫出匯入程式；內容則會讓個資離開本機。這條原則的完整說明見 `知能庫/個資與保密/以結構代替內容.md`。

## 已知限制

- 偵測得到 VBA 專案存在，但**不解析巨集程式碼**。若需要看巨集邏輯，要另外處理。
- 讀的是儲存格的**快取值**（Excel 上次存檔時算好的結果）。若活頁簿存檔前沒重算，值可能過期；公式本身則永遠正確。
- 合併儲存格只會在左上角那一格有值，其餘為空。跨欄表頭要自己往左找。
