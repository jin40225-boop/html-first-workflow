# 全資料夾個資去識別化

## 這個功能幫我做什麼

把一整個資料夾裡的真實個資**全部換成假的**，但**同一個人在所有檔案裡都換成同一個假名**。

```
王小明（在 A.xlsm）  →  測試案主003
王小明（在 B.csv）    →  測試案主003     ← 一致
王小明（在 C.docx）   →  測試案主003     ← 一致
王小明（在 D.db）     →  測試案主003     ← 一致
```

**為什麼一致性是關鍵**：處理過的資料還能拿來分析、還能拿來測試、還能拿來展示給人看。
如果每個檔案各換各的，關聯就斷了，那份資料就廢了。

處理範圍：`xlsm` / `xlsx` / `xls` / `csv` / `docx` / `db` / `pdf` / 純文字檔。

## 用在什麼時候

- 要把真實系統做成**可以拿出去展示的示範版**
- 要給 AI 或外部廠商一份**結構完全一樣但沒有個資**的資料
- 要建測試資料庫，但假資料太乾淨測不出真實問題

## 技術線

```
掃資料夾（跳過 .venv / __pycache__ / 指定目錄）
  ↓  依副檔名分派
xlsx/xlsm/xls  → openpyxl / xlrd 逐欄判斷 → 依欄名分類替換
csv            → 逐欄
docx           → 正則掃全文（身分證/電話/地址樣式）
db             → sqlite3 逐表逐欄
文字檔          → 正則掃全文
  ↓  全域對照表（跨所有檔案共用）
_name_map / _id_map / _addr_map / _phone_map / _contact_map
  ↓
直接覆寫原檔
```

## 三個核心設計

### 1. 欄名分類 + 全域對照表

```python
NAME_COLS    = {"個案姓名","身心障礙者姓名","姓名","服務使用者姓名","案主姓名",...}
ID_COLS      = {"身分證字號","身份證字號","身分證號","身份證號"}
ADDR_COLS    = {"戶籍地址","通訊地址","居住地址","地址"}
PHONE_COLS   = {"聯絡電話","電話","手機","行動電話","mobile_phone","home_phone"}
CONTACT_COLS = {"聯絡人","緊急聯絡人","照顧者姓名","家屬姓名","主要照顧者"}

_name_map: dict[str, str] = {}    # ← 全域，跨檔共用
```

**別名清單要窮舉。** 現場的表格欄名不會統一——「身分證」「身份證」都要收（前者是正字、後者是常見誤寫），中英文欄名也都要收。漏掉一個欄名，那一整欄的個資就會留在檔案裡。

替換時查對照表，沒有就新增一筆：

```python
if v not in _name_map:
    _name_map[v] = f"測試案主{len(_name_map)+1:03d}"
return _name_map[v]
```

### 2. 明確定義「什麼不換」

檔頭寫得很清楚：

> 不替換：**社工姓名**（非個資）、**案號**、**日期**、**統計數值**

這一行決定了處理後的資料還有沒有用。

- 案號不換 → 跨表關聯還在
- 日期不換 → 時序分析還能做
- 統計數值不換 → 報表數字還是對的
- 承辦人姓名不換 → 「誰負責哪些案」的分佈還看得出來（在這個情境下承辦人是職務資訊，不是受保護個資）

**每個專案的這條線不一樣，移植時第一件事就是重新畫。**

### 3. 沒有欄名時退回正則

`docx` 和純文字檔沒有欄位結構，只能靠樣式比對：

```python
RE_ID    = re.compile(r'\b[A-Z][12]\d{8}\b')
RE_PHONE = re.compile(r'0[89]\d{1,2}[-\s]?\d{3}[-\s]?\d{3,4}')
RE_ADDR  = re.compile(r'[一-鿿]{2,4}[縣市][一-鿿]{2,4}[鄉鎮市區][一-鿿]{2,10}[路街巷弄號\\d]+[號]?')
```

**姓名沒有正則可寫**（中文姓名和一般詞彙分不開），所以純文字檔裡的姓名只能靠「已經在對照表裡的舊值」去比對替換——**先跑結構化檔案建立對照表，再跑非結構化檔案**，順序不能反。

## 移植點

| 位置 | 要改的 |
|---|---|
| 檔頭 docstring | **「不替換」清單。移植第一件事就是重畫這條線** |
| `SKIP_DIRS` | 跳過的資料夾 |
| `NAME_COLS` ~ `CONTACT_COLS` | 你的表格實際用的欄名（含所有誤寫變體） |
| `_fake()` 的假值格式 | 「測試案主001」換成你要的樣式 |
| `RE_ID` / `RE_PHONE` / `RE_ADDR` | 非台灣資料要整組換掉 |

**可以整段照抄的**：全域對照表的結構、`_fake()` 的「查表→沒有就新增」模式、依副檔名分派的骨架。

## ⚠ 使用前必讀

**這支程式不備份，直接覆寫原檔**（檔頭原話：「不備份，直接覆寫（使用者已確認）」）。

移植時**強烈建議改掉**這個行為，至少加上：

- 預設輸出到另一個資料夾，要加旗標才覆寫（照 `K-GOV-001` 的做法：用 `--execute` 開啟寫入，不要用 `--dry-run` 關閉）
- 執行前自動備份整個資料夾
- 先跑一次只列出「會動到哪些檔案的哪些欄位」的預覽

原版之所以敢直接覆寫，是因為它的使用情境是「對著一份已經複製出來的副本跑」。**如果對正式資料跑一次，就沒有回頭路了。**

## 相依套件

```
openpyxl   （xlsx / xlsm）
xlrd       （舊版 xls）
python-docx（docx，若要處理）
```
`sqlite3`、`re`、`pathlib` 是標準函式庫。

## 已知限制

- **姓名在非結構化文字裡無法主動偵測**，只能替換「已經在對照表裡」的值。所以順序很重要。
- PDF 的處理能力有限（掃描檔完全無法處理）。
- 直接覆寫，無回復。
- 假姓名是「測試案主001」這種明顯假的字串——**這是刻意的**，讓人一眼看出這是處理過的資料，不會誤當真實資料使用。
