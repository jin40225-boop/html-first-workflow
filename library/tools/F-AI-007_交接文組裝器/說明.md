# 交接文組裝器（把驗收條件內嵌進給 AI 的請求）

## 這個功能幫我做什麼

要把一件工作交給外部 AI（例如貼到別的對話視窗、丟給另一支 AI 工具）時，
交接文如果只寫「我想要什麼」，AI 的產出常常要來回改好幾輪才會被接受——
因為「什麼樣的產出會被退」這件事，AI 事前根本不知道。

這支純函式做的事很單純：吃一份結構化的資料（頁面內容、目標、限制、待確認項），
組裝成一段可以直接複製貼上的純文字交接文。文字裡除了講「想達成什麼」，
還內嵌了一段**寫入面契約**——白話說就是「你的產出要用什麼方式送回來、
會用哪個管道落地、以下幾種情況一定會被拒絕」。

這樣 AI 收到交接文的當下就知道邊界在哪，產出自然會落在合法範圍內，
而不是先做出一個東西、拿去落地時才發現不合格。

## 技術線

```
結構化輸入（頁面清單、每頁的交接備註）
   │
   ├─1 篩出真的有填寫交接備註的頁面（跳過只是預設空殼的頁面）
   ├─2 逐頁組裝成一個小節：目標／指示／互動意圖／必留素材／避免事項／待確認項
   ├─3 附上固定的「寫入面契約」文字區塊
   │    （產出方式、落地指令、會被拒絕的情況——對齊實際落地通道的行為）
   └─4 附上「這段內容不會自動外送」的聲明
   │
   └→ 回傳一段純文字字串
```

### 為什麼這樣拆，而不是另一種做法

| 決定 | 選的 | 沒選的 | 為什麼 |
|---|---|---|---|
| 寫成什麼形式 | 不含 UI、不含網路呼叫的純函式（輸入資料，輸出字串） | 直接掛在 UI 元件裡，點一下按鈕就組裝並顯示 | 純函式可以直接單元測試——餵合成資料進去，斷言輸出字串包含哪些內容，不必掛起整個編輯畫面；也保證這段邏輯不會意外夾帶網路呼叫 |
| 契約內容寫在哪 | 寫死在這支函式裡，跟落地通道的原始碼放在同一個專案 | 寫在另一份文件裡，兩邊各自維護 | 契約文字對外承諾的是落地通道**實際會做的事**；文件與程式碼分開放，兩邊改動不同步時，交接文就會對 AI 承諾一件通道實際上不做的事 |
| 要不要自動送出 | 不送，只組字串，畫面上明講「不會自動外送」 | 順手接上 API 直接發送給外部 AI | 交接對象往往是使用者自己另開的 AI 對話視窗，這支函式不知道、也不該假設對方是哪一個服務；把「送出」這個決定留給人 |

## 核心手法

### 1. 只組裝真的填了內容的頁面，跳過空殼

```ts
function pageHasBriefContent(page: CoursePage): boolean {
  const brief = page.aiBrief
  if (!brief) return false
  return Boolean(brief.goal?.trim()) || Boolean(brief.instruction?.trim()) || Boolean(brief.interactionIntent?.trim())
    || brief.mustKeep.length > 0 || brief.avoid.length > 0 || brief.strictAssets.length > 0 || brief.pendingQuestions.length > 0
}
```

資料結構裡每一頁預設都帶著一份空的交接備註物件（欄位都是空字串或空陣列）。
如果不先篩掉這些空殼，交接文會塞滿一堆「目標：（空白）」的無意義小節，稀釋掉真正填了內容的頁面。

### 2. 寫入面契約的文字要跟落地通道的實際行為對齊，並在程式碼裡註明兩邊要一起改

```ts
/**
 * 寫入面契約：讓外部 AI 的產出天然落進合法通道。
 * 這段文字對齊落地通道（另一支腳本）的實際行為，兩邊改動時要一起改，
 * 不然這裡就會變成對外承諾了通道實際上不做的事。
 */
const WRITE_CONTRACT = [
  '你的產出方式：回傳一份完整的候選資料檔。',
  '它會以 <落地指令> 落地，該通道會用與編輯器相同的驗證器檢查，以下情況會被拒絕且不寫入任何位元組：',
  '<逐條列出驗證器實際會擋的情況>',
].join('')
```

這一段跟本資料庫另一條 `F-AI-006` 描述的落地通道是同一套機制的兩端：
`F-AI-006` 是實際擋的地方，這支函式是**把「會被擋在哪」提前講給 AI 聽**。
兩邊如果各自改了驗證規則卻沒有互相同步，交接文就會變成一句空話，AI 照著做了卻還是被退。

### 3. 明講「不會自動外送」，把送出的決定權留給人

```ts
const sections: string[] = [
  // ...其餘小節
  '## 重要聲明',
  '這段內容不會自動外送，需要你自己複製貼上到外部 AI 對話中。',
]
```

這支函式確實不 import 任何網路呼叫相關的模組——「不會自動外送」不是一句畫面上的口號，
而是可以直接從程式碼看出來的事實：函式簽章是「吃資料、吐字串」，沒有第三種可能。

## 移植點（要換掉的地方）

| 內容 | 位置 | 怎麼改 |
|---|---|---|
| `AiPageBrief` / `CourseProject` / `CoursePage` 型別 | 匯入的型別定義 | 換成你自己的資料結構；欄位（教學目標、互動意圖等）是專案專屬 |
| `BRIEF_STATUS_LABEL` 對照表 | 狀態文字 | 換成你自己的狀態列舉與顯示文字 |
| `WRITE_CONTRACT` 的內容 | 常數字串 | 逐條列出你自己落地通道實際會拒絕的情況；**內容要跟落地通道同步維護**，這是這支函式存在的意義 |
| `formatPageBrief` 逐欄位組裝 | 函式內容 | 換成你自己資料結構的欄位對應 |

**可以整段照抄不用改的**：純函式的整體結構（不含 UI、不含網路呼叫）、
「先篩有內容的項目再組裝」的做法、「內嵌寫入面契約」這個結構本身、
末尾「不會自動外送」的明示聲明。

## 已知限制

- **契約文字是手動維護的自然語言，不是自動從驗證器程式碼生成的。** 驗證規則改了，
  這裡的文字需要人手動跟著改；兩者之間沒有機制保證同步，全靠開發時的自律（見核心手法第 2 節的註解提醒）。
- **不驗證輸入資料本身的正確性。** 這支函式假設傳進來的 `CourseProject` 已經是合法資料，
  它只負責組裝文字，不做二次驗證。
