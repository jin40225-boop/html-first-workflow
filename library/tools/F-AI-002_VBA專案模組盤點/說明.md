# VBA 專案模組匯出與功能盤點

## 這個功能幫我做什麼

一個用了很多年的 `.xlsm`，裡面塞了幾十個 VBA 模組、幾千行程式碼，**沒有人知道哪個模組在幹嘛、哪些是備份、哪些還在用**。

這套工具鏈把整個 VBA 專案攤開來：

1. 每個模組匯出成獨立的 `.bas` 檔（UTF-8，可以版控、可以給 AI 讀）
2. 產出一張表：**模組 ｜ 行數 ｜ 程序數 ｜ 功能群 ｜ 功能摘要 ｜ 時間線索 ｜ 相似模組**
3. **算出模組之間的相似度**，直接告訴你「這兩個幾乎同版，可能是備份」

> 這是 `F-AI-001 舊 Excel 結構勘查器` 的姊妹作。
> **那支勘查資料結構（工作表、欄位、公式），這支勘查程式碼結構（模組、程序、重複）。**
> 一個舊 Excel 系統要交接，兩支都要跑。

## 技術線

```
.xlsm
  ↓  export_vba_inventory.ps1   Excel COM → VBProject.VBComponents
每個模組寫成 <名稱>.bas（UTF-8 with BOM）＋ _components.csv
  ↓  build_module_inventory.py
_module_inventory.csv      行數 / 程序數 / 功能群 / 時間線索
_module_similarity.csv     兩兩 Jaccard 相似度
  ↓  build_vba_text_table.py
VBA功能文字彙整_表格版.md   ← 給人與 AI 讀的最終報告
```

`run_vba_analysis_safe.ps1` 是把上面三步串起來的一鍵入口。
`build_vba_report_utf8.py` 是另一種輸出格式（詳細報告版）。

## 四個核心手法

### 1. 用 Excel COM 讀 VBProject，不是解析二進位

```powershell
$wb = $excel.Workbooks.Open($wbPath, $null, $true)     # 第三個參數 = 唯讀
foreach($comp in $wb.VBProject.VBComponents){
  $lines = $comp.CodeModule.CountOfLines
  $text  = $comp.CodeModule.Lines(1, $lines)
  [System.IO.File]::WriteAllText($outFile, $text, [System.Text.UTF8Encoding]::new($true))
}
```

`vbaProject.bin` 是私有二進位格式，硬解很難。**讓 Excel 自己吐出來最可靠。**

前提是要開啟「信任存取 VBA 專案物件模型」（Excel 選項 → 信任中心 → 巨集設定）。這是唯一的環境要求。

### 2. COM 物件一定要在 finally 裡收乾淨

```powershell
finally {
  if($wb -ne $null){ $wb.Close($false) | Out-Null }
  $excel.Quit()
  [void][System.Runtime.InteropServices.Marshal]::ReleaseComObject($excel)
  [GC]::Collect(); [GC]::WaitForPendingFinalizers()
}
```

**沒有這四行，Excel 程序會殘留在工作管理員裡**，跑幾次之後電腦上會有一堆看不見的 EXCEL.EXE 佔著記憶體，而且原檔會被鎖住。

### 3. 用 Jaccard 相似度找出「哪些其實是同一個模組的不同版本」

```python
def tokenize(text):
    return re.findall(r'[A-Za-z_一-鿿][A-Za-z0-9_一-鿿]*', text.lower())

def jaccard(a, b):
    set_a, set_b = set(a.keys()), set(b.keys())
    return len(set_a & set_b) / len(set_a | set_b)
```

兩兩比對所有模組，相似度 ≥ 0.70 的列進報告，再依行數差距判斷：

```python
if la == lb:                 diff = '幾乎同版（可能是備份/複製）'
elif abs(la - lb) > 80:      diff = '同核心但其中一版有較大增修'
else:                        diff = '同功能近似版，局部差異'
```

**這是整套工具最值錢的部分。** 這個專案有 176 個 `.bas` 檔，但真正不同的模組只有二三十個，其餘全是歷次備份。沒有這張相似度表，人要一個一個開來比。

**這個手法可以搬到任何「一堆檔案不知道哪些重複」的場合**，不限 VBA。

### 4. 用關鍵字把模組自動分群

```python
rules = [
  ('總表-子表同步',      ['runsync','sync_run_log','backup_sync']),
  ('匯入主流程/案件異動', ['執行匯入程序','建立新個案','家戶勾稽']),
  ('表單重置/下拉選單',   ['重置','dropdown','validation']),
  ('原始文字解析',       ['分析開始','getmatch','scankeywords']),
  ...
]
```

取命中關鍵字最多的那一群。**不精準，但夠用**——目的是讓人能一眼看出「這批是同步相關的、那批是報表相關的」，而不是產出一份權威分類。

另外還會從程式碼裡撈**時間線索**（`20xx/xx/xx`、`V1.2`、民國日期 `115xxxx`），推斷模組大致的年代。

## 已知限制

- **需要真的裝 Excel**，沒有純解析的路線。若要在無 Office 的伺服器上跑，只能改成解析 `vbaProject.bin`（難度高很多）。
- 只匯出標準模組（`Type == 1`）。表單模組（`.frm`）與類別模組（`.cls`）不會匯出程式碼，只列在 `_components.csv` 裡。
- 分群靠關鍵字，會有誤判。它是**導覽工具不是權威分類**。
- 兩兩比對是 O(n²)。176 個模組跑得動；上千個就要改成先分桶。
